# 安全规则

## 核心原则

知识库可以记录工作流程，但不应该保存秘密本身。

尤其当仓库可能被同步到 GitHub、被多个 agent 访问、或未来可能公开时，必须默认所有写入内容都有泄露风险。

---

## 严禁写入的内容

以下内容禁止写入知识库：

- 明文密码
- API key
- token
- 私钥
- cookie
- SSH private key
- 数据库连接密码
- 可直接登录服务器的完整凭据
- 完整账号密码表
- 未脱敏的个人身份信息
- 其他人的隐私信息
- 受限项目的内部敏感资料

---

## 服务器信息记录规则

可以记录：

```md
服务器用途：办公室自用计算节点
连接方式：通过 SSH config alias
推荐命令：ssh office-self
凭据位置：见本地私有配置，不写入知识库
```

不应记录：

```md
IP: xxx.xxx.xxx.xxx
username: xxx
password: xxx
token: xxx
private_key: xxx
```

如果必须记录内网 IP，也应避免同时记录账号、密码和完整登录方式。

---

## 凭据记录方式

如果 agent 需要知道凭据在哪里，应使用间接描述：

```md
凭据不保存在本知识库中。
请查看用户本地私有 SSH config、密码管理器或环境变量。
```

可以写：

```md
使用环境变量 `OPENAI_API_KEY`
```

不可以写：

```md
OPENAI_API_KEY=sk-xxxx
```

---

## 写入前安全检查

每次写入或更新笔记前，agent 必须检查：

1. 是否包含密码、token、key？
2. 是否包含可直接登录的完整信息？
3. 是否包含他人隐私？
4. 是否包含不应进入 GitHub 的路径或内部资料？
5. 是否可以改写为"凭据位置"而不是"凭据内容"？

如果有任何不确定，默认不要写入。

---

## 已经泄露时的处理

如果发现敏感信息已经写入知识库，应立即：

1. 删除或脱敏当前文件中的敏感内容
2. 提醒用户修改相关密码或 token
3. 提醒用户 Git 历史中可能仍保留旧内容
4. 建议使用 `git filter-repo`、重建仓库或 GitHub secret scanning 清理历史

不要只删除当前文件后就认为安全问题已经解决。

---

## 推荐写法示例

### 不推荐

```md
使用 paramiko 登录服务器：

username='user'
password='password'
```

### 推荐

```md
使用 paramiko 或 SSH config 登录服务器。

凭据不写入知识库。
请从本地私有配置或密码管理器读取。
```

---

## 对 agent 的额外要求

agent 不应主动要求用户提供密码、token 或私钥。

如果任务确实需要凭据，应建议用户使用：

- 环境变量
- 本地配置文件
- SSH config
- 密码管理器
- Secret manager

而不是把凭据贴进对话或写进仓库。
