# 记忆写入规则

## 核心判断标准

只有满足以下条件的信息，才适合写入知识库：

> 下次还会用到，且不写下来未来 agent 容易忘记、重复询问或重复踩坑。

知识库不是聊天记录，也不是临时草稿箱。它应该保存稳定、可复用、经过筛选的工作知识。

---

## 应该写入的内容

以下内容适合写入知识库：

### 1. 可复用操作流程

例如：

- 项目部署流程
- 服务器连接流程
- 调试步骤
- 数据处理流程
- 文档整理流程
- 文献检索流程

### 2. 项目结构和模块职责

例如：

- 某个代码项目的目录结构
- 重要模块分别负责什么
- 入口文件在哪里
- 常用脚本怎么运行
- 生成文件放在哪里

### 3. 反复踩过的坑

例如：

- 某个依赖版本不能用
- 某个命令在特定环境下会失败
- 某个服务器不能直接使用某工具
- 某种写法会导致隐藏 bug

### 4. 用户长期偏好

例如：

- 用户偏好的代码风格
- 用户偏好的论文表达方式
- 用户不希望 agent 使用的说法
- 用户常用的文件命名习惯
- 用户常用的科研符号约定

### 5. 重要决策及理由

例如：

- 为什么采用某种目录结构
- 为什么选择某个工具而不是另一个
- 为什么某个论文写法被保留或删除
- 为什么某个物理解释更稳妥

### 6. 领域知识和术语约定

例如：

- 项目中的专业术语
- 容易混淆的概念
- 写作中应该避免的误导性表述
- 某个研究方向的核心参考资料

---

## 不应该写入的内容

以下内容不应写入知识库：

### 1. 敏感信息

禁止写入：

- 明文密码
- API key
- token
- 私钥
- cookie
- 可直接登录的完整凭据
- 详细账号密码表
- 未脱敏的服务器敏感信息

如确实需要记录，应只记录"凭据在哪里查找"，不要记录凭据本身。

### 2. 一次性临时状态

例如：

- "今天下午要做什么"
- "刚刚跑了哪个命令"
- "某个临时文件在哪里"
- "当前任务做到哪一步"

这些内容适合出现在当前对话或临时 TODO 中，不适合长期知识库。

### 3. 未验证的猜测

如果只是推测，可以暂时记录在任务总结中，但不要写成稳定规则。

如果必须记录，请明确标注：

```md
## 验证状态
待验证
```

### 4. 容易过期的信息

例如：

- 当前软件版本
- 临时网页链接
- 会议时间
- 某个外部服务的当前状态
- 不稳定的 API 行为

如果必须写入，需要加更新时间和过期检查提醒。

### 5. 已经存在于代码或 README 中的信息

如果信息已经在项目 README、代码注释、commit message 或配置文件中清楚存在，不要重复写入知识库。

可以只写：

```md
详见项目 README 的 XXX 部分。
```

---

## 新建笔记前的检查

在新建笔记前，agent 必须先检查：

1. 是否已有同类笔记？
2. 是否应该更新已有笔记，而不是新建？
3. 是否需要同步更新对应目录的 `_index.md`？
4. 是否包含敏感信息？
5. 是否需要标注来源、置信度和更新时间？

---

## 更新已有笔记的原则

优先更新已有笔记，而不是创建大量相似笔记。

当新信息与旧信息相关时，应：

1. 打开已有笔记
2. 修改或追加相关部分
3. 保留必要历史说明
4. 更新"更新时间"
5. 如有冲突，参考 `conflict-resolution.md`

---

## 笔记命名规则

文件名使用 kebab-case：

```text
python-debug-workflow.md
git-proxy-setting.md
glueball-writing-style.md
server-login-policy.md
```

不要使用过长、含空格、含特殊符号的文件名。

---

## 每篇笔记推荐包含的信息

建议每篇笔记至少包含：

```md
# 标题

## 适用场景

## 核心结论

## 标准流程

## 常见坑

## 来源

## 置信度

## 更新时间
```

具体模板见 `note-template.md`。
