# 任务结束检查清单

每次 agent 完成一个任务后，应快速判断是否需要更新知识库。

---

## 一、是否需要沉淀？

任务完成后，检查：

- 这次任务中是否出现了未来可能复用的流程？
- 是否发现了新的项目结构、模块职责或文件位置？
- 是否踩到了一个未来可能再次遇到的坑？
- 用户是否表达了长期偏好？
- 是否形成了稳定的写作表达、代码模式或检索方法？
- 是否做出了以后需要记住的决策？

如果以上问题都是否，则不需要写入知识库。

---

## 二、应该新建还是更新？

写入前先检查：

1. 相关目录的 `_index.md`
2. 是否已有同类笔记
3. 是否应该追加到旧笔记中

优先更新已有笔记，避免碎片化。

---

## 三、安全检查

写入前必须确认：

- 没有密码
- 没有 token
- 没有 API key
- 没有私钥
- 没有可直接登录的完整凭据
- 没有他人隐私
- 没有不该公开的内部信息

如果不确定，默认不要写入。

---

## 四、质量检查

写入或更新笔记后，检查：

- 是否有清楚标题？
- 是否说明适用场景？
- 是否有核心结论？
- 是否有来源？
- 是否有置信度？
- 是否有更新时间？
- 是否更新了对应 `_index.md`？
- 是否避免了和已有笔记重复？

---

## 五、推荐结束动作

如果值得沉淀：

1. 选择对应目录
2. 阅读该目录 `_index.md`
3. 查找是否已有同类笔记
4. 新建或更新笔记
5. 更新 `_index.md`
6. 简短告诉用户更新了哪些内容

---

## 六、不应过度沉淀

不要为了"显得记忆在成长"而写入无价值信息。

以下情况不要沉淀：

- 只是一次性任务
- 只是普通聊天
- 只是临时计划
- 只是当前状态
- 信息已经在项目文件中
- 信息很快会过期
- 内容没有被验证
