# 冲突处理规则

当知识库中的旧信息与新信息、用户指令、项目代码或实际运行结果发生冲突时，按本规则处理。

---

## 信息优先级

一般情况下，优先级从高到低为：

1. 用户当前明确指令
2. 当前项目代码和实际运行结果
3. 最新 README / 官方文档
4. 知识库中最近更新且高置信度的笔记
5. 知识库中较旧或低置信度的笔记
6. agent 自己的推断

---

## 当用户当前指令与知识库冲突

用户当前明确指令优先。

但如果用户指令可能导致安全问题、数据丢失或明显错误，agent 应提醒用户。

例如：

- 用户要求把密码写入公开仓库：应拒绝或建议脱敏
- 用户要求删除重要文件：应提醒风险
- 用户要求跳过验证：可执行但应说明风险

---

## 当代码与知识库冲突

以当前代码为准。

处理方式：

1. 记录发现的冲突
2. 更新对应笔记
3. 在笔记中说明旧信息已失效
4. 更新时间
5. 如有必要，在 `_index.md` 中调整说明

---

## 当两篇笔记冲突

处理方式：

1. 比较更新时间
2. 比较来源
3. 比较置信度
4. 检查是否可以合并
5. 保留更可靠的信息
6. 删除或标注过期信息

不要让两篇笔记长期保留互相矛盾的结论。

---

## 当信息只是部分过期

不要整篇删除。

可以增加：

```md
## Deprecated / 已过期部分

以下内容已不再推荐：

- ...

原因：

- ...

替代方案：

- ...
```

---

## 当无法判断谁对谁错

如果无法判断，应：

1. 不要强行覆盖旧笔记
2. 标注"待验证"
3. 在任务回复中提醒用户
4. 必要时保留两个版本，并写清适用条件

示例：

```md
## 注意

当前存在两个可能流程：

- 方法 A：适用于旧环境，来源于 2026-xx-xx 笔记
- 方法 B：适用于新环境，来源于当前项目代码

尚未完全确认哪个应作为默认流程。
```

---

## 删除规则

只有在以下情况下才删除旧内容：

- 明确错误
- 明确泄露敏感信息
- 已有更完整笔记替代
- 用户明确要求删除
- 内容完全过期且无历史价值

否则优先标注过期，而不是直接删除。
